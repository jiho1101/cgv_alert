## Actual root causes

1. Primary `mcp.aka.page` returns HTTP 502 instead of usable timetable data.
   On 2026-10-14 03:00:33 UTC its body contained `CGV_RELAY_FAILED` and
   `upstreamStatus: 502`. The underlying reason inside that external relay is
   not visible; do not claim that this alone proves CGV is down.
2. The official BFF and legacy API probes returned HTTP 403. Both requested
   runs, 38481029479 and 38482370106, returned zero timetable indicators for
   current-day probes despite a successful Actions conclusion.
3. Official browser collection in production timed out. A separate cloud
   browser interaction with the real website DID render current Ulsan seats.
   Access therefore differs by client/environment. A cloud browser reading in
   this chat is not a deployed unattended collector.
4. The independent moviebara publication was stale: at 03:01:36 UTC, its
   manifest was generated at 2026-10-13 21:49:36.292270 UTC and its screenings
   source was updated at 21:48:05.308379 UTC, about 5h 13m earlier. HTTP 200
   and a correct content digest did not make those seats current.
5. The checker returned normally after all watched pages failed. Actions
   consequently showed success, masking a data-source outage.
6. Empty future responses were classified as structured successes; historical
   `last_cgv_success_at` could actually mean third-party response success.
   These were not sound evidence of current first-party collection.

## Continuation / genuine remaining blocker

The best eventual architecture is a permissioned first-party collector using
one theater date-discovery request, current-day sentinel validation and
incremental watched-date schedules; exact immutable CGV identity plus
transactional notification state; a separate scheduler/watchdog; genuine
per-date collection telemetry. This is a proposed architecture only. It was
not deployed as a new data source because admission evidence is absent.

Required next gate: obtain **documented permission for unattended CGV
read-only collection or a licensed timely seat feed**. This work did not send
external partnership/inquiry messages, purchase a service, create an account,
or expand credentials. A local machine or a different TLS client must not be
recommended as an unverified way around 403 or crawler policy.

Once permission exists, shadow-test current Ulsan rows with exact IDs and seat
fields across separate observations, measure source updates and actual opening
latency, then qualify the new collector before switching production. Retain
the old keys as aliases during any identity migration.

Known remaining risks: upstream outage; missing/stale future publication;
scheduling delay; unproven multi-source identity equivalence; ambiguous
Discord timeout after delivery but before acknowledgment (webhooks do not
give an exactly-once guarantee); lack of a demonstrated real December
opening; unobserved long-term behavior. Successful mocked retry tests must
not be described as solving these live uncertainties.

The current system continues permitted provider attempts and records their
actual failures. The daily follow-up and existing shadow/watchdog provide
continued observation; they cannot make unavailable upstream data available.
